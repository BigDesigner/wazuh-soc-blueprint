## 2. Critical & Major Defects Breakdown

### 🔴 DEFECT-01: Invalid DQL Syntax (Fatal Execution Failure)
- **Location:** `dashboards/SOC-Dashboard-6-Execution-Process.md` — Panel 5 (Line 172)
- **Problematic DQL:**
  ```dql
  (data.win.system.eventID:4688 OR data.win.system.eventID:1)
  AND data.win.eventdata.commandLine.length > 500
  ```
- **Root Cause:** DQL (Dashboards Query Language) does **not** support object method calls, scripting properties (`.length`), or dynamic string length evaluations. In OpenSearch Dashboards, executing this query results in a fatal search parse error: `Cannot search on length property of string`.
- **Impact:** Panel 5 is completely broken in OpenSearch.
- **Remediation:** 
  1. Approximate string length using wildcards in DQL:
     ```dql
     (data.win.system.eventID:4688 OR data.win.system.eventID:1)
     AND data.win.eventdata.commandLine:????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????????*
     ```
  2. OR leverage a dedicated Wazuh rule in `rules/local_rules.xml` (e.g. Rule 100400 evaluating string regex length `.{500,}`) and query `rule.id:100400` in the panel.

### 🔴 DEFECT-02: Zero-Result Field Dependency (Data Layer Defect)
- **Location:** `dashboards/SOC-Dashboard-3-Privilege-Escalation.md` — Panel 4 (Line 144)
- **Problematic DQL:**
  ```dql
  data.win.system.eventID:(4672 OR 4728 OR 4732 OR 4756)
  AND data.win.eventdata.ipAddress:*
  AND NOT data.win.eventdata.ipAddress:("-" OR "127.0.0.1")
  ```
- **Root Cause:** Windows Security Event IDs 4672 (*Special Privileges Assigned*), 4728 (*Member Added to Global Security Group*), 4732 (*Member Added to Local Group*), and 4756 (*Member Added to Universal Group*) **do not produce an `ipAddress` field** in Windows Security Event logs! Their native schema contains `SubjectUserName`, `SubjectLogonId`, `MemberSid`, and `TargetUserName`.
- **Impact:** Filtering with `AND data.win.eventdata.ipAddress:*` causes this panel to return **0 results permanently**, creating a false sense of security.
- **Remediation:** 
  - Windows events correlate actor source IP through logon sessions (`SubjectLogonId` mapped back to Event 4624).
  - Alternative approach: Pivot Panel 4 to **Target Host / Domain Controller Breakdown** (`agent.name` vs `subjectUserName`) or monitor privilege assignment across target workstations rather than expecting nonexistent IP fields.

### 🔴 DEFECT-03: D2-P4 Logic & Scope Discrepancy
- **Location:** `dashboards/SOC-Dashboard-2-RDP-Deep.md` — Panel 4 (Line 109)
- **Title:** `## Panel 4 — SOC | RDP | Internal | Timeline (4624/4625)`
- **Problematic DQL & Bucket:**
  ```dql
  data.win.system.eventID:4624 AND data.win.eventdata.logonType:10 AND data.win.eventdata.ipAddress:(10.38.1.* OR 172.16.16.*) AND NOT data.win.eventdata.targetUserName:*$
  ```
  Split series:
  ```markdown
  - Field: data.win.system.eventID
  - Size: 5
  - Custom Label: Event ID
  ```
- **Root Cause:** The panel title claims to compare successful (`4624`) and failed (`4625`) internal RDP logons, and the split series aggregates by `eventID`. However, the DQL query hardcodes `data.win.system.eventID:4624`! 
- **Impact:** Event `4625` is filtered out by the DQL query; the split series only renders a single color/value (4624), defeating the entire purpose of the panel.
- **Remediation:** Update DQL to:
  ```dql
  (
    (data.win.system.eventID:4624 AND data.win.eventdata.logonType:10)
    OR
    (data.win.system.eventID:4625)
  )
  AND data.win.eventdata.ipAddress:(10.38.1.* OR 172.16.16.*)
  AND NOT data.win.eventdata.targetUserName:*$
  ```

### 🟡 DEFECT-06: Event 4688 vs Sysmon Event 1 Field Mismatch
- **Location:** `dashboards/SOC-Dashboard-6-Execution-Process.md` — Panel 2 (Line 53)
- **Problematic DQL:**
  ```dql
  (data.win.system.eventID:4688 OR data.win.system.eventID:1)
  AND data.win.eventdata.parentImage:(*winword.exe OR *excel.exe OR *powershell.exe OR *cmd.exe)
  AND data.win.eventdata.image:(*whoami.exe OR *net.exe OR *nltest.exe OR *vssadmin.exe)
  ```
- **Root Cause:** Sysmon Event 1 uses `data.win.eventdata.parentImage` and `data.win.eventdata.image`. However, Windows Native Event ID 4688 uses `data.win.eventdata.parentProcessName` and `data.win.eventdata.newProcessName`.
- **Impact:** If an endpoint only has native Windows auditing enabled without Sysmon, Event 4688 will fail to match the query.
- **Remediation:** Align DQL to support both field namespaces:
  ```dql
  (data.win.system.eventID:4688 OR data.win.system.eventID:1)
  AND (data.win.eventdata.parentImage:(*winword.exe OR *excel.exe OR *powershell.exe OR *cmd.exe) OR data.win.eventdata.parentProcessName:(*winword.exe OR *excel.exe OR *powershell.exe OR *cmd.exe))
  AND (data.win.eventdata.image:(*whoami.exe OR *net.exe OR *nltest.exe OR *vssadmin.exe) OR data.win.eventdata.newProcessName:(*whoami.exe OR *net.exe OR *nltest.exe OR *vssadmin.exe))
  ```

### 🟡 DEFECT-07: Elastic ECS Field Name Drift in Dashboard 5
- **Location:** `dashboards/SOC-Dashboard-5-Threat-Intel-IOC.md`
  - **Panel 3 (Malware):** Columns list specifies `file.hash` and `file.path`. In Wazuh standard decoders, file metadata resides under `data.virustotal.sha1`, `syscheck.path`, `syscheck.sha256`, or `data.win.eventdata.hashes`.
  - **Panel 4 (DNS):** DQL specifies `data.query:(*.xyz OR ...)`. In Wazuh Windows Sysmon Event 22, the field is `data.win.eventdata.queryName`.
- **Impact:** Misaligned field paths cause blank table columns in standard Wazuh index patterns.

## 3. Overlap & Redundancy Analysis

### ⚠️ Overlap Issue A: D1-P2 vs D2-P2 (Accidental Redundancy)
- **D1-P2:** `rule.groups:authentication_failed AND data.win.eventdata.ipAddress:* AND NOT data.win.eventdata.targetUserName:*$`
- **D2-P2:** `data.win.system.eventID:4625 AND data.win.eventdata.ipAddress:* AND NOT data.win.eventdata.targetUserName:*$`
- **Analysis:** Both panels are Horizontal Bars ranking `data.win.eventdata.ipAddress` with size 15. Because D2-P2 does **not** filter for `logonType:10`, it captures ALL Windows authentication failures, making it virtually identical to D1-P2!
- **Recommendation:** D2-P2 MUST add `AND data.win.eventdata.logonType:10` to restrict its scope strictly to failed RDP attempts, eliminating the duplicate.

### ✅ Overlap Issue B: D1-P7 vs D4-P3 (Confirmed Complementary)
- **D1-P7:** Horizontal bar ranking users performing Network/SMB Logons (Type 3).
- **D4-P3:** Line chart tracking 5-minute spikes of SMB Logons over time.
- **Status:** Valid orthogonal views; cross-reference notes are already documented.

### ✅ Overlap Issue C: D2-P4 vs D2-P5 (Confirmed Complementary)
- **D2-P4:** Time-series stacked bar chart for internal RDP activity.
- **D2-P5:** Detailed investigation table (Source IP → User → Target Host).
- **Status:** Valid workflow pairing (Detection trend → Analyst drilldown).
